# 🌱 KODOMO WORLD

**公開版: https://shodai-nagamine.github.io/kodomo-world/**
（作品を追加するページ: https://shodai-nagamine.github.io/kodomo-world/add.html）

> 登録した作品画像・こども情報は、そのブラウザの中（IndexedDB / localStorage）だけに保存されます。サーバーへ送信されることも、他の人に見えることもありません。逆に、ブラウザのサイトデータを消すと作品も消えます（書き出し機能は未実装）。

## 概要

子どもが作った作品（絵・工作など）の写真を登録すると、Three.js製の3Dサンドボックス「作品世界」の島にキャラクターとして住み着き、ギャラリー表示やタイムライン（年齢別）で振り返れるフロントエンドのみのMVPアプリです。登録時に背景を抜いて輪郭を押し出せば「アクリルスタンド風の立体」として、それ以外は「切り抜きの立て看板」として島に立ちます。データはすべてブラウザ内（IndexedDBに画像Blob、localStorageにこども登録情報）に保存され、サーバー・データベース・AI機能は一切使用していません（背景除去・立体化もアルゴリズムのみでAIは不使用）。Three.js本体もCDNではなく `lib/` にローカル同梱しています。

## 📄 2ページ構成

このアプリは `index.html`（作品世界ページ）と `add.html`（作品を追加するページ）の2ページに分かれています。

- **`index.html`（作品世界ページ）**: 🌍 作品世界（3Dワールド）／🖼 ギャラリー／📖 タイムラインのタブと、右に作品詳細パネル。ヘッダの「＋ 作品を追加」から `add.html` へ移動する。
- **`add.html`（作品を追加するページ）**: まず作者（こども）を選択・登録し、続けて「1. 作品の写真 → 2. 3Dにする → 3. 作品の情報」の順で作品を登録する。ヘッダの「← 世界にもどる」で `index.html` へ戻れる。

ページの行き来:

```
index.html --「＋ 作品を追加」--> add.html
add.html   --「← 世界にもどる」--> index.html
add.html   --登録完了後「🌍 世界で見る」--> index.html?focus=<作品id>（その作品を選択してカメラが寄る）
add.html   --登録完了後「つづけて追加する」--> add.html のフォームに戻る（作者・日付は残したまま）
```

読み込むスクリプトもページごとに異なる（詳細は次節）。`core.js`（データ層）は両ページが読み込むが、世界ページは3D描画のため `world3d.js` を、追加ページは画像解析のため `modeler.js` をそれぞれ読み込む。**追加ページはThree.jsを読み込まず**（＝3D描画コードを持たず）、逆に世界ページは `modeler.js` を読み込まない。

## 🚀 起動方法

IndexedDBを使うため `file://` で直接開くと保存できません。必ずローカルサーバー経由で開いてください。

推奨: 同梱の `serve.py` を使う。

```bash
python3 serve.py
# ポートを変えたい場合は引数で指定（既定8949）
python3 serve.py 9000
```

`serve.py` はレスポンスに常に `Cache-Control: no-store` を返す。素の `python3 -m http.server` だとブラウザがJS・ESモジュール（`world3d.js`など）をキャッシュしてしまい、編集した内容が反映されないことがある（実際にこれで嵌まったため追加した）。

起動後、ブラウザで http://localhost:8949 を開きます（IndexedDBを使うため `file://` では動作しません）。

## 👶 こども登録機能

- こどもの登録・編集は追加ページ（`add.html`）の「作者（こども）」パネルにある「＋ こどもを登録」またはこどもチップの✎から開くモーダルで行う（世界ページにはこども登録UIはない）。
- 保存先は localStorage の `kw_children`（キー: `kw_children`）で、各要素は `{id, display_name, birth_date, birth_year, created_at}`。表示名は必須、生年月日は任意。
- 直前に選択していたこどもは `kw_selected_child`（こどものid文字列）に保存され、次回起動時も選択状態が復元される。
- **年齢の自動計算**: こどもに生年月日が登録されていれば、制作日を入力/変更するたびに `calcAge(birth, dateStr)` が生年月日と制作日の差分から「◯歳◯ヶ月」を計算し、年齢欄に自動入力する（手動での上書きも可能）。生年月日が未登録で生年（`birth_year`）のみわかる場合は、年のみのおおよその年齢を計算する。
- **表示名は登録側が正**: 作品データ自体には登録時点の `child_name` も保存されるが、表示時（詳細パネル・ギャラリー・タイムライン）は `nameOf()` が `child_id` から `children` 配列の現在の `display_name` を優先して解決する。そのため、こどもの表示名をあとから変更すると、既存の作品の表示もまとめて新しい名前に更新される（登録済みこどもが見つからない場合のみ、保存時の `child_name` にフォールバックする）。なお3Dワールドのキャラクターラベルは作品名（title）であり、作者名は表示されない。
- **削除の制限**: 編集モーダルの「このこどもを削除する」は、そのこどもの `child_id` を持つ作品が1件でも残っていると無効化され、「作品が◯件あるため削除できません」と表示される。作品をすべて削除するか作者を変更しない限り、こどもの登録は削除できない。

## 🧊 作品を3Dにする（`modeler.js` / add.htmlの「2. 3Dにする」）

追加ページ（`add.html`）で作品の写真を選ぶと、フォームは「1. 作品の写真 → 2. 3Dにする → 3. 作品の情報」の3段になる。2段目で背景除去と、アクリルスタンド風の立体化（押し出し）の下準備を行う。**AI・外部APIは一切使わず**、`modeler.js` がブラウザの Canvas 2D とアルゴリズムだけで完結させる。

### `window.KWModel.analyze(blob, opts)`

- classic script（`<script src>` で読み込む。import/exportは使わない）として `window.KWModel` に公開される主API。
- `opts`（すべて省略可）: `tolerance`（既定0.16、背景と判定する色距離のしきい値）／ `maxSize`（既定900、解析時に長辺を縮小する上限px）／ `maxPoints`（既定160、輪郭1本あたりの最大頂点数）／ `removeBackground`（既定true）
- 戻り値: `{cutout, width, height, contours, coverage, ok, reason}`
  - `cutout`: 背景除去後（失敗時は元画像のまま）のPNG Blob
  - `contours`: 輪郭ポリゴンの配列。各点は画像サイズで0〜1に正規化した `[x, y]`。面積の大きい順
  - `coverage`: 前景（背景でないと判定された）画素の割合
  - `ok`: 解析が成功したか。`false`のときは背景を抜かない結果（`contours`は画像全体を囲む矩形1枚）にフォールバックし、`reason`に理由の文字列が入る
  - `width` / `height`: 解析時に実際に使った（縮小後の）画像サイズ

### 処理の流れ

1. EXIF回転を反映して読み込み（`createImageBitmap(blob, {imageOrientation:'from-image'})`）、長辺が `maxSize` 以下になるよう縮小する
2. 画像外周2%の帯を5bit/chに量子化したヒストグラムに集計し、最頻ビンの平均色を背景色と推定する（`estimateBackgroundColor`。単純平均でなく最頻ビンを使うことで、白い紙にできた影などの少数派色に引っ張られにくくしている）
3. **外周と連結した領域だけ**をフラッドフィル（明示的キューによるBFS、再帰なし）で背景と判定する（`floodFillBackground`）。色差はLab空間のユークリッド距離・CIE76（`rgbToLab` / `colorDistance`）で測る。外周とつながっていない限り、背景色と同じ色でも前景として残るため、**絵の中に描かれた白は消えない**
4. 前景率（`coverage`）が0.95超（背景を判定できなかった）または0.03未満（前景が小さすぎる＝背景を抜きすぎ）なら失敗と判定し、背景を抜かない結果に `ok:false` でフォールバックする
5. 微小な孤立ブロブを除去し（`removeSmallBlobs`、全体面積の0.05%未満を除去）、3×3のボックスブラーでマスクをなめらかにしてフリンジを軽減する（`boxBlurMask`）。このアルファ値をcutout画像に反映する
6. 連結成分をラベリングし、面積の大きい成分から Moore-Neighbor tracing（Jacob's stopping criterion、`traceBoundary`）で前景の外周画素を直接たどって輪郭を抽出する。Ramer–Douglas–Peucker法（`simplifyRDP`）でepsilonを段階的に大きくしながら `maxPoints` 以下になるまで簡略化し（それでも収まらない場合は最終手段として一様間引きで確実に上限を守る）、向きをCCWに統一してから正規化座標に変換する
7. 輪郭が1本も取れなければこれも失敗として `ok:false` でフォールバックする（`reason:'輪郭を抽出できませんでした'`）

### Node からの利用

ファイル末尾の `module.exports` ガードにより、`rgbToLab` / `colorDistance` / `estimateBackgroundColor` / `floodFillBackground` / `labelComponents` / `removeSmallBlobs` / `boxBlurMask` / `traceBoundary` / `polygonSignedArea` / `ensureCCW` / `simplifyRDP` / `simplifyToMaxPoints` / `extractContours` / `KWModel` の各純粋関数を個別にNodeから`require`できる（Node上では`window`が未定義のため無害。ブラウザでは`window.KWModel`が主APIであることに変わりはない）。

### フォームの「2. 3Dにする」ステップ（`add.js`）

- 写真を選ぶと `window.KWModel` があれば自動的に解析が始まり、切り抜きプレビュー（`#cutCanvas`）に切り抜き画像＋輪郭（オレンジの破線）を重ねて描画する
- 「背景を抜いて立体にする」チェック（`#use3d`、既定オン）: オフにすると解析をスキップし、写真をそのまま板として置く
- 「背景の抜き具合」スライダー（`#tol`、6〜32%）: `tolerance` に対応する。動かすたびに220ms待ってから再解析する（`runModelingSoon`。連打しても古い解析結果が新しい結果を上書きしないよう `modelSeq` で世代を管理している）
- 「厚み」スライダー（`#thick`、4〜26 → 保存時に/100した値が `depth`）: 動かしても解析はやり直さず表示ラベルのみ更新し、保存時の押し出し厚みとして使われる
- **`PREVIEW_SIZE`（420px）／ `FINAL_SIZE`（640px）の二段構え**: プレビュー中は軽い `PREVIEW_SIZE` で解析する（900pxで解析すると約1.8秒かかり、スライダー操作のたびに固まって重くなるため）。フォーム送信時に `FINAL_SIZE` で解析し直してから保存する（高解像度側の解析が失敗した場合はプレビューの解析結果をそのまま使う）
- `modeler.js` が読み込めない環境（`window.KWModel` が存在しない）では「2. 3Dにする」チェックを無効化し、「立体化の部品を読み込めなかったので、写真のまま板で置きます。」と表示する。解析自体が失敗（`ok:false`）した場合も同様に、その作品は写真のままの板（`original_image`）として保存される

## 🌍 3Dワールド

`world3d.js` がThree.jsで描画する島の世界。作品は「切り抜きの立て看板（板）」または「押し出された立体（アクリルスタンド風）」としてキャラクター化され、島の上にランダム配置される（立体化の詳細は「🧊 作品を3Dにする」を参照）。

### 操作方法（`#worldHint` に表示される案内と対応）

- **ドラッグで見まわす**: 何もない場所をドラッグすると、カメラが島の周りを旋回する（`mode:'orbit'`）
- **ホイールで近づく／離れる**: マウスホイールでカメラの距離（`cam.dist`）を変更する
- **キャラクターをドラッグで移動**: キャラクターをつかんでドラッグすると島の上を移動でき、離した位置がIndexedDBの `position_x` / `position_y` に保存される
- **クリックで選択／選択解除**: キャラクターをドラッグせずクリックすると選択（オレンジの輪が表示され詳細パネルに反映）、何もない場所をクリックすると選択解除される
- **放置すると自動回転**: 最後の操作から7秒（`IDLE_SPIN_MS = 7000`）操作がないと、カメラが自動的にゆっくり回転しはじめる

### 作品数による段階的な変化

`world3d.js` の `tierOf(n)` が作品数から段階（tier）を、`radiusOf(n) = 7 + √n × 2.5` が島の半径を決定する。段階が上がると `applyTier()` が装飾（木・岩・花）・池・雲・家を追加で表示する。

| 段階 | 作品数の条件 | 島の半径の目安 | 装飾（木・岩・花） | 池 | 雲 | 家 |
|---|---|---|---|---|---|---|
| 0 | 0作品 | 7 | 0個 | なし | 0個 | なし |
| 1 | 1〜2作品 | 約9.5〜10.5 | 4個 | なし | 2個 | なし |
| 2 | 3〜5作品 | 約11.3〜12.6 | 9個 | **登場** | 3個 | なし |
| 3 | 6〜9作品 | 約13.1〜14.5 | 16個 | あり | 4個 | なし |
| 4 | 10〜19作品 | 約14.9〜17.9 | 26個 | あり | 6個 | **2軒登場** |
| 5 | 20作品以上 | 約18.2〜（作品数の平方根で際限なく拡大） | 40個 | あり | 7個 | 5軒 |

装飾（木・岩・花）は `buildProps()` が起動時に72個ぶんの位置を一度だけ生成し、`['tree','rock','tree','tree','flower','rock',...]` という固定順を先頭から繰り返し割り当てる。段階が上がるごとにこの固定順のまま出現数（上表の個数）が増えるだけで、既存の装飾の位置は並び替わらない（＝作品が増えても世界がガラッと作り直されず、広がっていくように見える）。段階が上がった瞬間は画面上部に「🌍 世界が広がった！」の通知が一時的に表示される。

### 立体キャラクター（アクリルスタンド風）

`shape`（輪郭ポリゴン）を持つ作品は、`buildExtruded()` が `THREE.ExtrudeGeometry` で輪郭を押し出した立体として表示される（`shape`を持たない作品は従来どおり切り抜きなしの板のまま）。

- 前後の面（押し出しのキャップ）には作品の切り抜き画像（`cutout`）をマテリアル0番として貼り、側面（押し出しの壁）には紙の小口のような色（`0xfff3e2`）をマテリアル1番として貼る（アクリルスタンド風の見た目になる）
- 板と違って**向きを持つ**: `rotation_y`（`item.yaw`）が指定されていればその向き、指定がなければ島の中心から見た配置角度（`atan2(x, z)`）＝**島の外向き**を既定の向きにする
- **選択するとその場でゆっくり回る**: 選択中のキャラクターは内部の`spin`角がフレームごとに`dt×0.55`ずつ増え続けて基準の向きに足し込まれ、選択を解くと`spin`が`×0.96`ずつ減衰して元の向きへ戻る
- シルエットの高さで大きさを揃える: 輪郭のバウンディングボックスから、板と同じ高さになるよう拡大率`k`を計算する（画像いっぱいに描かれているとは限らないため。横長の作品は幅の方で頭打ちにし`k`は最大2.4倍まで）
- **シルエットの底で接地する**: 押し出しジオメトリのバウンディングボックス最小Yを使って、実際の絵の底が地面付近（`y=0.18`）に接するよう`model.position.y`を補正する

開発用に `KW3D.inspect()` がある。コンソールから呼ぶと、各キャラクターが立体（`solid`）か板か、位置、押し出しジオメトリのサイズ、テクスチャ読み込み済みか、輪郭の頂点数、現在の島の半径などをまとめて返す。

## 🖼 ギャラリー

`gallery.js`（`window.KWGallery.render`）が世界ページ（`index.html`）のタブ「🖼 ギャラリー」に表示する一覧コンポーネント。

- **表示切替**: 🖼 ギャラリー（サムネイルのカードグリッド）／ ☰ リスト（横一列の行表示）を切り替えられる
- **並び替え**: 制作日が新しい順（既定） / 制作日が古い順 / 年齢順 / 作者順（かな順）
- **作者で絞り込み**: 「全員」または登録済みこどもごとに絞り込める。絞り込み対象のこどもが削除されて一覧になくなった場合は自動的に「全員」に戻る
- 表示モード・並び順・絞り込みの状態はコンポーネント内のstateに保持され、再描画（作品の追加・削除など）をまたいでリセットされない

## 💾 データの保存場所と構造

### IndexedDB

- DB名: `kodomo-world`
- ストア名: `artworks`（keyPath: `id`）
- レコードのフィールド:
  - `id`: 作品ID（例 `a-xxxxx-xxxxx`）
  - `world_id`: 固定値 `w-default`
  - `child_id` / `child_name`: 登録時点の作者ID・作者名（表示は基本的に `child_id` から現在の登録名を解決する）
  - `title`: 作品名（子どもがつけた名前）
  - `description`: 本人の説明
  - `age_years` / `age_months`: 制作時の年齢（年・月）
  - `created_at`: 制作日（`YYYY-MM-DD`）
  - `uploaded_at`: 登録日時（ISO文字列）
  - `position_x` / `position_y`: 世界内の位置（%、0〜100）
  - `scale`: キャラクター表示サイズの倍率（登録時にランダムで0.85〜1.2程度に決定）
  - `appearance_type`: 背景除去＋立体化できた作品は `extruded_cutout`、写真のまま板で置く作品は `original_image`
  - `original`: オリジナル画像のBlob（無加工）。**Original First**――`cutout`や`shape`をどれだけ作っても`original`自体は一切加工しない
  - `display`: 表示用に長辺900px・JPEG品質0.86へ縮小したBlob（板表示や「元の作品を見る」でのライトボックス表示に使用。立体表示では代わりに`cutout`を使う）
  - `cutout`: 背景除去後の画像Blob（`modeler.js`が生成するPNG、透過あり）。`appearance_type`が`extruded_cutout`のときのみ値を持つ
  - `shape`: 輪郭ポリゴンの配列（`modeler.js`の`contours`。各点は0〜1に正規化した`[x, y]`座標）
  - `depth`: 立体の押し出し厚み（フォームの「厚み」スライダー値を100で割った値）
  - `rotation_y`: 立体の向き（ラジアン）。現状は登録時は常に`null`で保存され、`null`のときは世界側で島の外向きが既定の向きとして計算される
  - `metadata`: `{filename, size, type, model}`（元ファイルの情報。立体化できた作品は`model`に`{coverage, tolerance, points}`＝解析時の前景率・背景の抜き具合・輪郭の総頂点数も記録される）

`cutout`（と`shape`）を持たない作品――「2. 3Dにする」をオフにした場合、解析に失敗した場合、`modeler.js`が読み込めない環境で登録した場合、および本機能が入る前に登録済みだった作品――は、`appearance_type`によらず3Dワールド上では板として表示される（`asWorldItem`が`cutout`と`shape`の両方が揃っている場合のみ立体として扱う）。

### localStorage

- `kw_children`: こども登録の配列。各要素は `{id, display_name, birth_date, birth_year, created_at}`
- `kw_selected_child`: 直前に選択していたこどものid

## ⚠️ 注意事項

- データはすべてブラウザ内（IndexedDB / localStorage）のみに保存されます。サーバーへの送信・バックアップは一切行われません。
- ブラウザプロファイルの削除やサイトデータの消去（「閲覧履歴を消去」等）を行うと、登録した作品・こどもの情報はすべて失われます。
- バックアップ・エクスポート機能は未実装です。重要なデータは元の画像ファイルを別途手元に保管してください。
